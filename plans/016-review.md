# Phase 016 final review — 2048-token detector windows

The isolated 1024- and 2048-token SIMD packages were built from the same pre-Phase-019 source except for `WINDOW_TOKENS`. Their SHA-256 values are `4af0cd4f9989301223778e1ffd315e1057e6651e658848694578f98567f68d43` and `a25b13d768468ad1e5f8fec74450af9dcb0efa807ccfcd44e8d61506c0606b4c`. The V17 bundle and 10,000-character fixture were fixed. Chrome 153, on the quiet machine after V19c training, ran three alternating paired rounds of 20 worker calls per package. Median of round medians was 394.8 ms versus 312.2 ms, a repeatable 82.6 ms (20.9%) reduction. All six first-result hashes matched, with 139 entities. Browser additional memory after calls was approximately 12.08 MB versus 14.44 MB; the API does not expose instantaneous peak, so no peak-memory claim is made. The latter remains below the 60 MB additional-memory budget. The 150 ms latency target still fails. Raw observations are private at `internal/reports/m7/window-size-browser.json`.

The full browser result, including offsets and confidence, was identical for the 20 longest reviewed documents per country (100 total, five countries) between isolated packages. After applying the 2048 constant to tracked source alongside the independently reviewed Phase-019 merge fix, the final release wasm package (`18d7353eba902cde090cd0d25b1e32100e7743af7095a254eb28cdc37761da56` SIMD SHA-256) again produced identical full output on all 100 against the original 1024 package. These are selected long development documents, not a complete 877-document accuracy rescore; the package comparison found no changed predictions on them. Phase 019 separately found no output change on all 877 documents for V17/V19c. Private reports: `window-size-long-doc-outputs.json` and `window-size-final-long-doc-outputs.json`.

The overlap (384) and trusted-margin (64 each side) remain unchanged, preserving the 256-token entity coverage inequality. The source module's worked example was updated to match two windows instead of four. All 180 release unit tests and release integration tests passed, including window coverage and merge tests; release Clippy and format passed. Baseline and SIMD release wasm packages built. Two wasm golden vectors passed in headless Chrome using the installed version-153 ChromeDriver directly; `wasm-pack test` initially selected a cached version-154 driver and failed before tests ran. No model, `models/` bundle, or site was changed. Phase 016 is retained as a measured runtime improvement, not a release gate pass.
